# 0004. 기기가 ping에 연결 정보를 실어 응답 (구 "보조 하트비트")

상태: 대기
날짜: 2026-09-30
출처: ADR-0003 (임대 갱신 주체를 서버로 옮기며 잃은 것)

## 문제

서버 → 기기 ping만으로는 조용히 죽은 기기(네트워크 단절)를 늦게 감지한다. TCP 쓰기는 상대 수신 확인 없이 성공으로 돌아오므로, 재전송 포기까지 몇 분이 걸릴 수 있다.

## 제안

기기가 주기적으로 HTTP 요청을 보내되, 의미를 "기기 생존 신호"로 한정한다. `last_seen`만 갱신하고 `server_id`를 쓰거나 키를 만들 자격은 없다.
대안으로 TCP keepalive 설정을 짧게 조정하는 방법이 있다.

## 채택 조건

기기 생존 감지 지연이 실제 요구사항이 될 때. 이 프로젝트의 실험(같은 호스트 kill -9)에서는 RST가 즉시 오므로 필요 없다.

## 결정 기록

- 2026-09-30 대기. PRD 11절에서 이관.
- 2026-10-01 제안을 구체화. 처음 설계(기기 하트비트)가 틀렸던 이유는 기기가 보내서가 아니라 하트비트에 "어느 연결인지"가 실려 있지 않아서였다. 기기는 `connected` 이벤트로 자기 서버와 연결 epoch을 안다. ping을 받을 때마다 (server_id, epoch)을 실어 HTTP로 응답하고 임대 갱신을 그 응답에만 묶으면, 좀비는 응답을 받지 못해 갱신할 수 없고, RST가 오지 않는 단절도 "N초간 응답 없음"으로 감지된다. ADR-0006의 epoch이 그대로 쓰인다. 시뮬레이터, 엔드포인트, 갱신 경로가 모두 바뀌므로 1단계 범위 밖.
