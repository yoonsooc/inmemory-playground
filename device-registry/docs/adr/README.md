# ADR (Architecture Decision Record)

설계 결정 하나를 문서 하나로 남긴다. 결정 자체보다 "왜 그렇게 정했고 무엇을 포기했는가"를 적는다.
결정이 뒤집히면 기존 문서를 고치지 않고 새 문서를 쓰고, 기존 문서의 상태를 "대체됨"으로 바꾼다.

| 번호 | 제목 | 상태 | 날짜 |
|---|---|---|---|
| [0001](0001-shared-registry-in-valkey.md) | 연결 정보의 공유 기록을 Valkey 해시 + TTL로 둔다 | 채택 | 2026-09-11 |
| [0002](0002-sse-for-server-to-device.md) | 서버 → 기기 채널로 SSE를 쓴다 | 채택 | 2026-09-30 |
| [0003](0003-server-side-lease-renewal.md) | 임대 갱신 주체를 기기에서 연결 주인 서버로 옮긴다 | 채택 (원안 대체, 0006으로 보완) | 2026-09-29 |
| [0004](0004-disconnect-cleanup-rules.md) | 연결 해제 시 자기 기록만 원자적으로 지운다 | 채택 (삭제 조건은 0006으로 변경) | 2026-09-11 |
| [0005](0005-command-routing-via-pubsub.md) | 명령은 서버별 Pub/Sub 채널로 연결을 쥔 서버에 보낸다 | 채택 (구현하고 검증함) | 2026-09-30 |
| [0006](0006-connection-epoch-for-lease-writes.md) | Valkey에 쓸 때 연결 번호(epoch)를 비교한다 (좀비 연결이 새 연결의 기록을 덮어쓰지 못하게) | 채택 (구현하고 검증함) | 2026-10-01 |

상태: 제안 → 채택 → (대체됨 | 폐기)

형식:

```
# NNNN. 제목
상태 / 날짜
## 맥락        무엇이 문제였나
## 결정        무엇을 하기로 했나
## 근거        왜 그것인가
## 대안        무엇을 검토했고 왜 아닌가
## 결과        얻는 것, 잃는 것, 후속 작업
```
