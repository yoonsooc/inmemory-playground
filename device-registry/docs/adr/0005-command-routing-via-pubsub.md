# 0005. 명령은 서버별 Pub/Sub 채널로 연결 주인에게 보낸다

상태: 제안 (4단계 구현 전)
날짜: 2026-09-30

## 맥락

운영자의 `POST /devices/{id}/command`는 nginx를 거쳐 아무 서버에나 도착한다. 그 서버가 연결 주인이 아니면 기기에 직접 보낼 수 없다.

## 결정 (제안)

1. 명령을 받은 서버는 `device:{id}` 해시에서 `server_id`를 읽는다. 없으면 OFFLINE으로 응답한다.
2. `server_id`가 자기 자신이면 로컬 emitter로 바로 보낸다.
3. 아니면 채널 `server:{server_id}`에 명령을 발행한다. 각 서버는 기동 시 자기 채널만 구독한다.
4. 구독한 서버는 로컬 맵에서 emitter를 찾아 SSE로 보낸다. 없으면(기록과 실제가 어긋난 경우) 경고 로그를 남긴다.

## 근거

- 채널을 서버별로 두면 명령이 모든 서버에 뿌려지지 않는다. 기록에서 주인을 찾아 그 서버에게만 보낸다. 레지스트리(ADR-0001)가 있어야 이 라우팅이 가능하다.
- 4번의 "없으면 경고"가 기록과 실제의 어긋남을 드러내는 관측 지점이다. ADR-0003의 설계가 맞다면 이 로그는 서버 죽음 후 TTL 창 안에서만 나와야 한다.

## 검토할 것

- Pub/Sub는 전달을 보장하지 않는다(구독자가 없으면 버려짐). 이 프로젝트에서는 감수한다. 보장이 필요하면 Stream이나 별도 큐가 필요하지만 비목표다.
- 클러스터에서 Pub/Sub 메시지는 모든 노드로 전파된다. 규모가 크면 Sharded Pub/Sub(`SPUBLISH`)를 검토한다. 이 프로젝트 규모에서는 무관하다.
- 응답: 명령 POST는 "발행했다"까지만 보장한다. 기기 수신 확인(ack)은 백로그.

## 결과

- 얻는 것: 명령을 어느 서버에 보내도 된다. 운영자와 nginx는 서버 구성을 몰라도 된다.
- 잃는 것: 서버 죽음 후 TTL 창 안에 온 명령은 죽은 서버의 채널로 발행되어 유실된다. README 한계에 적는다.
